Automation framework architecture

One mental model for Selenium, Playwright, Appium, Rest Assured, and Locust. Design, defend, and scale a test system.

Reference layers

flowchart TB
  CI["CI shards workers artifacts"] --> Tests
  Tests --> Flows["Business flows"]
  Flows --> Pages["Pages / API clients / Locust"]
  Pages --> Driver["Driver factory Strategy Decorator"]
  Driver --> Cross["Config logging reporting data secrets"]

Interview sentence: separate what you test, how flows are expressed, where locators/API live, and how you run.

Layer rules

LayerOwnsMust not own
TestArrange act assert tagsLocators, sleeps, raw HTTP
FlowMulti-step journeysBrowser APIs in every test
Page / APILocators, waits, clientsBusiness asserts (keep light)
DriverCreate/quit, capabilitiesAssertions

Golden: one context/driver per test, no sleep, stable locators, independent data, artifacts on fail, env from outside, flake is a bug.

Playwright vs Selenium (isolation)

flowchart TB
  Browser --> Ctx1["Context test A"]
  Browser --> Ctx2["Context test B"]
  Ctx1 --> PageA
  Ctx2 --> PageB

Playwright: Browser → Context (isolated cookies) → Page → Locator with auto-wait. Selenium: one WebDriver per test thread; never a static singleton.

Appium / API / load

Appium: client → server → UiAutomator2/XCUITest → device. Screen objects like POM. One session per device.

Rest Assured: domain clients + POJOs + env spec. Chain create → extract id → update.

Locust: share API clients; gate p95; investigate p99 spikes with deploy, errors, DB, cache, downstream.
