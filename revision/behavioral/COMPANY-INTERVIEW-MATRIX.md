# Company interview matrix — SDET II / III / Lead

This is a practical map of what companies commonly emphasize. Exact loops vary by team, but these patterns show up repeatedly.

## Amazon

### SDET II

- medium coding signal can be strong
- framework and API depth
- heavy Leadership Principles follow-ups
- SQL / debugging / CI may appear

### SDET III

- stronger coding bar, sometimes close to SDE II signal
- system design for test platform, grid, orchestration, scalability
- concurrency, distributed thinking, ownership stories

### Lead

- platform roadmap
- org influence
- metrics and quality strategy
- bar-raiser style deep follow-ups on failures and trade-offs

## Apple

### SDET II / Senior

- coding often moderate but still important
- strong emphasis on product quality, craft, release confidence
- collaboration with dev / PM / design
- mobile and ecosystem awareness can matter by team

### SDET III / Lead

- quality strategy and execution
- deep debugging and ownership
- influence and detail orientation
- often less LP-style than Amazon, but very probing on substance

## Google

### SET / SDET-style loops

- coding and debugging tend to matter a lot
- design for testability, reliability, and scale
- “Googliness” style behavior and collaboration
- automation is expected to look like software engineering

## Meta

### SDET / quality engineering style

- speed with quality trade-offs
- impact and metrics
- mobile/web scale
- experiment and release confidence mindset

## Microsoft

### SDET / quality / test engineering

- collaboration and growth mindset
- cloud / enterprise / services quality concerns
- CI/CD, integration, release trains
- debugging and practical engineering depth

## Uber / DoorDash / fintech / high-scale product companies

### Common signals

- medium coding bar
- distributed systems, Kafka, observability, incident/debugging awareness
- reliability and platform quality
- strong system design relevance for senior roles

## What to prepare regardless of company

### Technical

- Java coding: easy + medium + selected advanced
- OOP and design patterns at practical depth
- framework architecture
- API, SQL, debugging
- concurrency, distributed systems, test platform design
- observability, security, CI/CD

### Behavioral

- 8–10 STAR stories
- ownership
- conflict/disagreement
- failure and recovery
- mentoring / influence
- metrics and business impact

## Company-specific adaptation rule

Use the same core stories, but change the emphasis:

- Amazon: LP + data + decision quality
- Apple: craft + cross-functional quality + detail
- Google: technical depth + collaboration + scale
- Meta: impact + speed + iteration
- Microsoft: growth mindset + partnership + platform quality
