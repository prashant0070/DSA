Phase 1

Linear structures as objects

Build arrays, lists, stacks, and queues as real Java classes. Client code depends on an interface so you can swap the implementation.

Three questions for every structure

  1. What is the object? fields and invariants
  2. What is the contract? Stack<T>, Queue<T>
  3. What can swap? ArrayStack vs LinkedStack
flowchart LR
  Client --> StackI["Stack T"]
  StackI --> ArrayStack
  StackI --> LinkedStack

Polymorphism: same push/pop, different internals.

Dynamic array

Definition Contiguous slots. Logical size vs capacity. When full, allocate 2× and copy. Add at end is amortized O(1) because expensive resizes are rare.
flowchart LR
  S0["size 3 capacity 4"] --> S1["add 4th: still O1"]
  S1 --> S2["add 5th: copy to capacity 8"]

This is how ArrayList works.

OpTime
get / set iO(1)
add at endO(1) amortized
insert frontO(n) shift

Singly linked list

Definition Nodes with value + next. Head is the first node or null. Private inner class Node hides the wiring. addFirst / removeFirst are O(1). Index get is O(n).
flowchart LR
  H["head"] --> N1["1"]
  N1 --> N2["2"]
  N2 --> N3["3"]
  N3 --> Null["null"]

Reverse: prev, curr, next — flip arrows in place.

Stack — LIFO

Definition Last in, first out. Interface: push, pop, peek, isEmpty, size. ArrayStack uses the end of a dynamic array. LinkedStack pushes at the head.
flowchart TB
  Top["top: C"] --> B["B"]
  B --> A["A bottom"]

Use: parentheses, undo, DFS, monotonic stack. Use dsa.linear.Stack, not java.util.Stack, in this phase.

Queue — FIFO

Definition First in, first out. offer at back, poll from front. Circular array: head and tail wrap with modulo so poll does not shift the whole array.
flowchart LR
  Head["head"] --> A["A"]
  A --> B["B"]
  B --> Tail["tail C"]

Use: BFS, scheduling. LinkedQueue keeps head and tail pointers.
