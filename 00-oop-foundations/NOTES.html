Phase 0

OOP foundations

You learn the Java object model that every later data structure uses. A class is the blueprint; an object is one instance in memory. This page expands the Markdown notes with diagrams and tighter definitions.

1. Class and object

Definition — class A class is a named blueprint: fields (state) + methods (behavior) + constructors (how to start valid). It is not data by itself.
Definition — object (instance) An object is one allocation of that blueprint. new BankAccount("Ada") and new BankAccount("Bob") are two separate objects with their own balances.
Definition — constructor A special method that runs once at new. Its job is to leave every invariant true. If the owner is blank, throw before the object exists.
Definition — this The current object. Needed when a parameter has the same name as a field: this.owner = owner. 
flowchart LR
  Class["Class BankAccount"] -->|"new Ada"| ObjA["Object Ada balance 0"]
  Class -->|"new Bob"| ObjB["Object Bob balance 0"]

One class, two objects. Changing Ada’s balance never changes Bob’s.

BankAccount a = new BankAccount("Ada");
BankAccount b = new BankAccount("Bob");

2. Encapsulation and invariants

Definition — encapsulation The object owns its data. Fields are private. Callers use methods. That is how you stop account.balanceCents = -50.
Definition — invariant A rule that must stay true after every public method. BankAccount: balance ≥ 0 and amounts > 0. Counter: 0 ≤ value ≤ max. Temperature: never below absolute zero.
Definition — getter vs setter A getter exposes a copy of state. A setter is not automatic. Only add one if that change is a legal operation. 
sequenceDiagram
  participant Client
  participant Account as BankAccount
  Client->>Account: deposit(500)
  Account->>Account: requirePositive
  Account->>Account: balance += 500
  Client->>Account: withdraw(9999)
  Account-->>Client: IllegalStateException

Illegal operations are rejected; the object stays valid.

IllegalArgumentException = caller passed a bad value. IllegalStateException = the object is valid, but this action is not allowed now (overdraw).

3. Inheritance vs composition

Definition — inheritance (is-a) Circle extends Shape means a Circle really is a Shape and can sit in a Shape variable. Use only when substitution is honest (Liskov).
Definition — composition (has-a) The object holds another object and delegates. HashSet has a HashMap. LRU cache has a map and a list. Default to this: less coupling.

5. Polymorphism

Definition One compile-time type, many runtime types. Shape s = new Circle(3); s.area(); runs Circle.area(). The client depends on the contract, not the concrete class.

  StackIface --> ArrayStack

Same calls: push and pop. Different internals. That is Phase 1.

6. Generics

Definition — type parameter T A placeholder the caller fills: Box<String> holds String. The compiler checks it so you do not cast and do not get ClassCastException.
Definition — bound T extends Comparable<T> means T can compare to itself. Trees and heaps need this. 
Box<String> names = new Box<>();
names.set("Ada");
String n = names.get();

7. equals and hashCode

== vs equals == on objects is identity (same memory). equals is value, if you define it.
Contract If a.equals(b) then a.hashCode() == b.hashCode(). Override both. Same fields. equals(null) is false. HashMap in Phase 2 depends on this.

Value objects (Point, Invoice) implement both. Identity objects (mutating BankAccount) usually should not — two accounts with the same balance are still different accounts. Java record generates equals/hashCode from components.
