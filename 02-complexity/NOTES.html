Theory

How to calculate time and space

Interviewers want a reasonable approach, an analysis of what you wrote, and an upgrade when n grows.

Notation

Big-O Upper bound — “at most this growth.” Default interview answer = worst-case time.
Omega Ω Lower bound — “at least.”
Theta Θ Tight bound — both O and Ω.

Drop constants and lower-order terms. n → ∞.

flowchart LR
  A["O1"] --> B["O log n"]
  B --> C["O n"]
  C --> D["O n log n"]
  D --> E["O n2"]
  E --> F["O 2n"]

Faster (left) to slower (right) for large n.

Time — recipe

  1. Name n (length, nodes, edges).
  2. Count loops, recursion, and how the size shrinks.
  3. Keep the dominant term.
ShapeTime
Nested loops both to nO(n²)
Two loops one after anotherO(n)
Halve n each stepO(log n)
Visit each tree/graph node onceO(n) or O(V+E)
fib without memoO(2ⁿ)
Merge sortO(n log n)
flowchart TB
  Merge["merge sort"] --> Half["split n/2"]
  Half --> Recurse["log n levels"]
  Recurse --> Work["n work per level"]
  Work --> Total["O n log n"]

Hidden costs

CodeActual
Arrays.sortO(n log n)
ArrayList.containsO(n)
HashMap.getO(1) average
TreeSet.containsO(log n)
String += in a loopO(n²)

Space

Auxiliary space Extra memory your algorithm allocates, not counting the input unless they ask “total space.”
PatternExtra space
Few variables, two pointersO(1)
HashMap of n keysO(n)
Recursion depth dO(d) stack
BFS queue width wO(w)

Two Sum map: O(n) time, O(n) space. Sorted two pointers: O(n) time, O(1) space.

Interview script

  1. Brute force and its complexity.
  2. Optimized approach and complexity.
  3. Trade-off (time vs space).
  4. Walk a tiny example.

On every solution comment: Time, Space, Why.
